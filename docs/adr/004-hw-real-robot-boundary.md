## 背景

MineWorld 真机线（SO-101 / JetRover / 后续 G1·Go 系列）面向台式机浏览器 + 键鼠遥操，不依赖 Pico/WebXR（该线归仓外 `mine-world-arm`）。真机侧的桥接服务（`arm-bridge`）是商业闭源资产：含真机资源、串口拓扑、部署凭证。本仓为公开开源仓，必须在架构上把「可开源部分」与「私有资产部分」一刀切清。

## 决策

1. **黑盒对接**：`arm-bridge` 对本仓而言是一个实现不可见的外部 WS 服务。Gateway 仅作其 WS 客户端，经薄翻译层（`hw_*` 后端）把 MW `cmd`/`state` 映射为外部协议子集。
2. **本仓只含**：开放协议子集（`schemas/`）、`hw_*` 适配层、`hw_fake` 仿真后端、Godot 键鼠前端、录制 schema、公开机械参数表（关节名/弧度限位/HOME——不含部署信息）。
3. **永不入库**：主机名/IP/端口/token/串口路径/部署脚本/真机标定原始数据。连接串走环境变量（`MW_HW_BRIDGE_URL` / `MW_HW_BRIDGE_TOKEN`），本地配置仅入 gitignore 的 `docs/ops.local.md`。
4. **安全边界在边缘**：急停、软限位 clamp、速率上限、鉴权、断线归零全部由 bridge/边缘侧负责；Gateway 只透传与录制，不做真机安全兜底。
5. **无真机可开发**：`hw_fake` 后端（关节积分 + 限位 + HOME）必须独立跑通全链路冒烟，保证开源贡献者零硬件参与。

## 理由

- 与 [21](../21-ecosystem-federation.md)「统一前台对接外部执行能力」同一理念：本仓是前台与协议 SSOT，不吞并外部实现。
- 翻译层集中一处 → 外部协议演进时漂移面最小；`hw_fake` 让 CI/冒烟/新贡献者不碰真机。
- 安全职责留在贴硬件的边缘侧，与真机行业惯例（急停不靠远端 UI）一致。

## 后果

- 真机演示依赖仓外服务可用性；公网 demo 降级策略 = `hw_fake`。
- 协议子集变更需双仓协调；本仓侧以契约测试钉住。
- G1/Go 等新机型 = 新增一个 `hw_*` 后端 + 一张公开参数表，不动客户端协议。
